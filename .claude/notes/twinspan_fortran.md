## 1回の分割の流れ (`CLASS` の 107-200 行)

1. `RECODE` → `WEIGHT` (稀種の重み下げ) → `RA` (対応分析の第1軸) → 固有値を記録
2. `XMAXMI` で軸の最大・最小を取り，**`AXMAX > -AXMIN` となるよう必要なら符号を反転**する
   (長いほうの端を正にする規約)
3. `CRMIN = AXMIN*CRLONG`，`CRMAX = AXMAX*CRLONG`，`CRMID`・`CRHALF` を作る
4. **`POLISH` をちょうど 2 回** (`IREWT = 2`)．毎回そのあと
   `CRMID = (AXMIN+AXMAX)/2`，`CRHALF = 0.5*CRLONG*(AXMAX-AXMIN)` と更新する
5. **分割点は `CRMID`**．`X(I) >= CRMID` が正群，`X(I) <= CRMID` が負群 (159-160, 166-167 行)
6. `CLOSER` で，2つの子のどちらが「兄弟群」に似ているかを見て左右を決める (番号付けの規約)
7. 指標種: `INDSCO` で帯の外の標本だけを数え，`Y(J) = YY(J)/AXPOS - Y(J)/AXNEG`
   (**相対頻度の差**) を作り，`TOPIND` が `FEEBLE = 0.1` で候補を絞る
8. **指標種の個数は 1..NIND を全部試し，誤分類が最小になる個数を選ぶ** (216-225 行)

## `POLISH` の中身 (`twinsub21.f`)

コメントに書いてあるとおり，**2つの序列を作って足す**．

1. 軸の範囲から帯を作る: `CUTMID=(AXMAX+AXMIN)/2`，`CUTHLF=(AXMAX-AXMIN)*0.5*CRCUT`，
   `CUT1=CUTMID-CUTHLF`，`CUT2=CUTMID+CUTHLF`
2. `INDSCO` が **帯の外の標本だけ**で各種の出現を数える (`Y`=負側，`YY`=正側，
   `AXNEG`・`AXPOS` は各群の重み合計)
3. 各種について
   - `PREF = (AYY-AY)/(AYY+AY)` (相対頻度による選好．**ecan の式と同じ**)
   - `FREQ = AYY+AY` を `FRQLIM` で頭打ち
   - **`PREF` を ±`PRLIM`(=0.5) でクリップ**し，`|PREF|<0.001` は 0.001 にする
     (**足切りではなくクリップ**)
   - `COLWGT = CCWT * (FREQ/FRQLIM)^ICWEXP * (|PREF|/PRLIM)^IPREXP`
     → **頻度に比例し，選好の 4 乗に比例する連続重み**
   - `Y(J) = PREF/PRLIM` (−1〜1 に正規化した選好)
4. **序列1**: `Y` を `COLWGT` で重み付けして標本ごとに加算し，行の重みで割る．
   さらに `max|X|` で割って正規化する
5. **序列2**: 種の重みを基本重み `CCWT` だけに戻し，`Y` の**単純平均** (出現種数で割る)
6. **`X = 序列1 + 序列2`**

## `WEIGHT` の重み下げ (`twinsub18.f`)

```
AY = (種の出現の重み合計) / (標本の重み合計)     # 相対頻度
if (AY >= FRQLIM) AY = FRQLIM                     # 0.2 で頭打ち
COLWGT = CCWT * ((AY/FRQLIM)^ICWEXP * (1-CWTMIN) + CWTMIN)
```

**`vegan::downweight()` とは違う**．vegan は「最も多い種に対する比」で決めるが，
原典は**絶対的な相対頻度 0.2 を基準**にし，**下限 0.01** を置く．
いま ecan は vegan 式なので，固有値が 0.005 ほどずれているのはこれが原因の可能性が高い．

### `CLOSER` も実装した (2026-08-27)

原典は分割した2つの半分の順序を「親の隣の群に似ているほうを先に」置く (`CLOSER`)．
同じ規則を `tw_closer()`・`tw_swap()` として実装した．

- 種ごとに `PREF = (|AY0-AY1|/(AY0+AY1)/0.3)` を 1 で頭打ちして **4 乗**し，
  参照群での頻度 `AY` に掛けて「正側らしさ − 負側らしさ」を積む．
  中間的な種 (`1-PREF` の重み) の寄与は，選好の強い種を上回らないよう切り詰める．
- 参照するのは**兄弟群**と**叔父群** (親の兄弟)．合成の符号は `IC mod 4` で決まる．
- **比べるのは，その節に出現する種だけ** (原典は `RECODE` 後の列を見る)．
  ここを絞らないと深い節で左右が食い違う．**これが最後の詰まりどころだった**．

**結果: 5 データで群の番号と各分割の固有値まで原典と完全一致**．

### まだ再現していないこと: 種の分類

**原典の種の分類は，擬似種行列の転置ではない**．R 側の `twinspan.R` (400-448 行) が
入力を作り直してから `CLASS` を `isec = 2` で呼ぶ．

1. 標本の分類から `spmat[群, 種]` = その群での種の出現数 (擬似種の水準ぶんを数える) を作る．
2. **階層を上へ積み上げる** (`spmat[i %/% 2, ] += spmat[i, ]`)．終端群だけでなく
   **すべての内部節**が対象になる．
3. 各群・各種について**忠実度の比**を作る:
   `rat = (群の中での頻度) / (群の外での頻度)`
   (`spmat[cl,sp] * (clsum[1]-clsum[cl]) / (clsum[cl] * (spmat[1,sp]-spmat[cl,sp]))`)．
4. **各群を 3 つの擬似標本に開く**．cut level は比の **0.8 / 2 / 6**．
   つまり種 × (3 × 群数) の 0/1 行列が種の分類の入力になる．
5. 重み: **種の行の重みはその種の総出現数** (`rrwt = spsum`)，
   **群の列の重みは群の大きさ**で，階層を 1 段上がるごとに `sqrt(2)` 倍し，
   さらに **2 番目・3 番目の cut level は 2 倍**する (`clsum <- c(1,2,2)*clsum`)．
6. この行列に対して，標本のときと同じ `CLASS` を回す．

### 決め手: 種の分類は指標種を使わない (`MIND = 0`)

R 側の 2 回目の `.Fortran("class", ...)` の**第4引数が `0L`** で，これが `MIND` にあたる．
`CLASS` は `IF (MIND.EQ.0) GOTO 100` で**指標種の段階をまるごと飛ばし**，
`IZD = (1+MZ)/2 = 8`，`IIZD = IZD`，`ISD = 0` とする．
`REPORT` の分類規則に当てはめると，**帯は無く，`zone > 8`**，すなわち
**研磨後の軸の範囲の中点で分割**することになる．

引数の対応が名前で分かりにくく (`nspec` → `MM`，`jnam` → `ICLASS`，`inflag` → `JNAM`)，
`0L` が `MIND` だと気づくまでに時間がかかった．**呼び出し側の引数の並びを
最後まで確かめるべきだった**．

### 実装した (2026-08-27)．ただし完全一致には至っていない

`tw_species_data()` として上の 1-6 をそのまま実装し，`polish = "hill"` の既定にした．
行の重みを扱えるよう `tw_ra()`・`tw_indsco()`・`tw_downweight()` に `rw` を足した
(**`WEIGHT` は頻度を行の重みで加重して数えている**．ここは実装中に見つけた)．

**標本の分類は変わらず，5 データで原典と完全一致のまま**．
**種の群は原典に近いが一致しない** (dune で 11 群 vs 12 群)．

原因は `spmat` の作り方の細部と見ている．R 側の作り方を読むと，
擬似種の索引が水準ごとに並んでいる (level-major) ため，
**水準 2 以上の擬似種の数え上げが「その標本で最後に見た水準 1 の種」へ加算される**
書き方になっている (`if (idat[i] <= n) j <- idat[i]` の `j` が持ち越される)．
意図した動きとは思えないが，そのとおりに真似ても一致しなかった．
次の 3 通りを試して，いずれも不一致:

| 数え方 | dune の群数 (原典 11) | varespec (原典 11) |
|---|---|---|
| 水準の数 (採用) | 12 | 13 |
| 在不在のみ | 11 | 12 |
| 水準の繰り上がりを真似る | 13 | 14 |

**種の並び (`tw_two_way()` の行の順序) は原典と違いうる**が，
標本の分類には影響しない．ここから先を詰めるなら，
`spmat` に相当する中間結果を原典側から取り出して突き合わせるのが早い．

### 実装で効いた点 (読まないと分からなかったもの)

- `INDSCO` は帯の外の標本だけを数えるのではなく，**中心からの距離に比例した
  なだらかな重み**で数える (帯の縁で 1 に飽和)．
- `POLISH` の選好は**足切りではなくクリップ**．全種が寄与し，重みは
  **頻度 × 選好の 4 乗**．
- 分割点は重心ではなく**研磨後の軸の範囲の中点**．
- **`FIND` が帯の境界と指標種の閾値を同時に最適化**する (誤分類最小．
  同点は群の均等さ → 閾値の位置 → 帯の中心度の順に破る)．
  帯は中心に固定ではなく**ずれる**．これが最後の決め手だった．
- `REPORT` は，帯の外は序列で，**帯の中だけ指標種得点で**割り当てる．
- `ZONEUP` は二元表の帯分けではなく，**この帯分けそのもの**だった (前の記述は誤り)．
